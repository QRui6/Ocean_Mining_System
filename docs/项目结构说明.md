## 📂 目录说明

### src/ - 源代码目录
所有的源代码都放在这里，包括组件、样式、工具函数等。

**优点：**
- 清晰的代码组织
- 便于模块化管理
- 符合现代前端项目规范

**子目录：**
- `components/` - Vue 组件
- `assets/` - 静态资源
- `utils/` - 工具函数（可选）
- `stores/` - 状态管理（可选）
- `router/` - 路由配置（可选）

### docs/ - 文档目录
所有项目文档集中管理。

**包含：**
- 项目说明文档
- 开发指南
- API 文档
- 部署文档

### .vscode/ - 编辑器配置
VS Code 的项目级配置。

**包含：**
- 编辑器设置
- 推荐扩展
- 调试配置

### 环境变量文件
- `.env` - 所有环境通用
- `.env.local` - 本地开发（不提交到 Git）
- `.env.development` - 开发环境
- `.env.production` - 生产环境

## 🔄 与旧结构的对比

### 旧结构（混乱）
```
项目根目录/
├── components/          # 组件直接在根目录
├── App.vue             # 源文件散落在根目录
├── main.js
├── constants.js
├── vite.config.ts      # 配置文件混在一起
├── 各种文档.md         # 文档散落各处
└── ...
```

### 新结构（清晰）
```
项目根目录/
├── src/                # 源代码集中管理
│   ├── components/
│   ├── App.vue
│   ├── main.js
│   └── constants.js
├── docs/               # 文档集中管理
├── 配置文件            # 配置文件在根目录
└── README.md
```

## ✅ 优化的好处

### 1. 清晰的分类
- 源代码在 `src/`
- 文档在 `docs/`
- 配置在根目录

### 2. 易于维护
- 找文件更快
- 结构更清晰
- 符合行业规范

### 3. 便于扩展
- 添加新组件到 `src/components/`
- 添加新文档到 `docs/`
- 添加新资源到 `src/assets/`

### 4. 团队协作
- 新成员快速上手
- 统一的项目结构
- 减少沟通成本

## 📝 文件命名规范

### 组件文件
- 使用 PascalCase：`MyComponent.vue`
- 单文件组件使用 `.vue` 扩展名

### JavaScript 文件
- 使用 camelCase：`myUtils.js`
- 常量文件：`constants.js`

### 文档文件
- 使用中文或英文：`快速开始.md` 或 `quick-start.md`
- 使用连字符分隔：`api-documentation.md`

## 🚀 如何使用

### 添加新组件
```bash
# 在 src/components/ 目录创建
touch src/components/NewComponent.vue
```

### 添加新文档
```bash
# 在 docs/ 目录创建
touch docs/新功能说明.md
```

### 添加静态资源
```bash
# 在 src/assets/ 目录添加
cp image.png src/assets/
```

## 🔍 路径引用

### 在组件中引用
```javascript
// 引用其他组件
import MyComponent from './components/MyComponent.vue';

// 引用常量
import { MY_CONSTANT } from './constants.js';

// 使用别名（@指向src目录）
import MyComponent from '@/components/MyComponent.vue';
```

### 在 HTML 中引用
```html
<!-- 引用入口文件 -->
<script type="module" src="/src/main.js"></script>
```
