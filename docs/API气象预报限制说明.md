# API气象预报限制说明

## 问题现象

使用 `weather_time` 参数获取未来时间的气象数据时，API返回的数据全部为 N/A 或无效值。

## 问题原因

### API文档说明
```
weather_time: utc时间，Unix时间戳。不填写则查询最近时间的气象数据。
```

### 实际测试结果
- **不传 weather_time**：返回当前气象数据 ✅
- **传入未来时间**：返回无效数据（N/A）❌

### 结论
船讯网API的 `weather_time` 参数虽然存在，但**不支持未来时间的气象预报**，或者需要特殊的API权限。

## 解决方案

### 当前实现
所有航线点都使用当前时间的气象数据：

```javascript
// 不传 weather_time 参数，获取当前气象
const result = await getWeatherByPoint(point.lng, point.lat);
```

### 数据说明
- **时间显示**：表格中显示的是"预计到达时间"
- **气象数据**：实际是"当前时刻"的气象数据
- **适用场景**：短期航线（1-2天内），气象变化不大

## 对比分析

### 理想方案（API支持未来预报）
```
点1: 12/20 10:00 → 获取 12/20 10:00 的气象
点2: 12/20 12:00 → 获取 12/20 12:00 的气象
点3: 12/20 14:00 → 获取 12/20 14:00 的气象
```

### 当前方案（API不支持未来预报）
```
点1: 12/20 10:00 → 获取当前气象（12/20 10:00）
点2: 12/20 12:00 → 获取当前气象（12/20 10:00）
点3: 12/20 14:00 → 获取当前气象（12/20 10:00）
```

## 影响评估

### 短期航线（< 24小时）
- **影响**：较小
- **原因**：短期内气象变化不大
- **建议**：可以使用当前气象数据作为参考

### 中期航线（1-3天）
- **影响**：中等
- **原因**：气象可能有变化
- **建议**：定期刷新数据（每6-12小时）

### 长期航线（> 3天）
- **影响**：较大
- **原因**：气象变化较大，当前数据参考价值有限
- **建议**：
  1. 分段规划，每天更新
  2. 接入其他气象预报服务
  3. 结合多源数据

## 替代方案

### 方案1：定期刷新（已实现）
- 每5分钟自动刷新气象数据
- 手动点击"刷新"按钮
- 适合短期航线

### 方案2：接入其他气象服务
可以考虑接入专业气象预报服务：
- 中国气象局API
- OpenWeatherMap
- Weather.com API
- 其他商业气象服务

### 方案3：混合策略
- 当前气象：使用船讯网API
- 未来预报：使用其他气象服务
- 数据融合：综合多源数据

### 测试1：不传 weather_time
```bash
GET /GetWeatherByPoint?key=xxx&lng=120.5&lat=30.2
```
**结果**：✅ 返回有效数据
```json
{
    "windspeed": 9.4,
    "waveheight": 2.7,
    "temperature": 19.3
}
```

### 测试2：传入当前时间
```bash
GET /GetWeatherByPoint?key=xxx&lng=120.5&lat=30.2&weather_time=1734652800
```
**结果**：✅ 返回有效数据（与测试1相同）

```json

**结果**：❌ 返回无效数据或N/A

## 建议

### 短期建议
1. 使用当前气象数据
2. 定期刷新（每6-12小时）
3. 在UI上明确标注"当前气象"

### 长期建议
1. 联系船讯网确认是否支持未来预报
2. 评估是否需要升级API权限
3. 考虑接入其他气象预报服务
4. 建立多源数据融合机制

⚠️ 注意：

```

## 总结

船讯网API的 `weather_time` 参数目前不支持未来时间的气象预报。系统已调整为使用当前气象数据，适合短期航线使用。对于长期航线，建议定期刷新数据或接入其他气象预报服务。
