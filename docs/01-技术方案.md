               │ HTTP / WebSocket

│  - 气象数据 API                          │
│  - AIS 航线 API                          │

└──────────────┬──────────────────────────┘
               │
┌──────────────▼──────────────────────────┐
│         数据层                           │

### 数据库
- **PostgreSQL 14+** - 关系型数据库
- **PostGIS** - 地理扩展
- **Redis 7+** - 缓存

### 部署
- **Docker** - 容器化
- **Nginx** - 反向代理
- **阿里云 ECS** - 服务器

## 三、为什么选择这些技术？

### Cesium.js vs Mapbox vs Leaflet

| 特性 | Cesium | Mapbox | Leaflet |
|------|--------|--------|---------|
| 3D 支持 | ✅ 原生 | ⚠️ 有限 | ❌ 无 |
| 粒子系统 | ✅ 强大 | ❌ 无 | ❌ 无 |
| 性能 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| 学习曲线 | 陡峭 | 中等 | 简单 |

**选择 Cesium**：因为需要 3D 地球、粒子动画、大数据量渲染

### Node.js vs Python

| 特性 | Node.js | Python |
|------|---------|--------|
| 与前端统一 | ✅ JavaScript | ❌ 不同语言 |
| 实时通信 | ✅ Socket.io | ⚠️ 需要额外库 |
| GRIB2 处理 | ⚠️ 需要工具 | ✅ pygrib 强大 |
| 部署 | ✅ 简单 | ✅ 简单 |

**选择 Node.js**：因为与前端统一，实时通信方便

### PostgreSQL vs MongoDB

| 特性 | PostgreSQL | MongoDB |
|------|------------|---------|
| 地理查询 | ✅ PostGIS | ⚠️ 有限 |
| 事务支持 | ✅ 强大 | ⚠️ 有限 |
| 数据一致性 | ✅ 强 | ⚠️ 弱 |
| 灵活性 | ⚠️ 结构化 | ✅ 灵活 |

**选择 PostgreSQL**：因为需要地理查询、数据一致性

## 四、核心技术难点

### 难点 1：GRIB2 数据解析

**问题**：气象数据是 GRIB2 格式，需要转换为 JSON

**解决方案**：
```bash
# 使用 grib2json 工具
npm install -g grib2json

# 转换命令
grib2json -d -n -o output.json input.grib2
```

### 难点 2：大数据量渲染

**问题**：全球气象数据有 100 万+ 个点，直接渲染会卡顿

**解决方案**：
1. 数据抽稀：只渲染可见区域
2. LOD：根据相机高度调整密度
3. WebWorker：后台处理数据
4. 粒子系统：用 GPU 渲染

### 难点 3：时序动画

**问题**：需要播放过去 7 天 + 未来 7 天的气象变化

**解决方案**：
1. 预加载所有时间点数据
2. 使用 requestAnimationFrame 控制播放
3. 缓存已加载的数据
4. 提供播放/暂停/快进控制

### 难点 4：航线气象匹配

**问题**：如何获取航线上每个点的气象数据？

**解决方案**：
1. 将航线分段（每 10km 一个点）
2. 对每个点进行空间插值
3. 获取该点的风浪流数据
4. 缓存结果避免重复计算

## 五、性能目标

- **帧率**：≥ 60 FPS
- **数据加载**：< 3 秒
- **时序切换**：< 500ms
- **航线分析**：< 2 秒
- **内存占用**：< 2 GB

## 六、技术风险

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| GRIB2 解析失败 | 中 | 高 | 备用 Python 脚本 |
| 性能不达标 | 中 | 高 | 数据抽稀 + LOD |
| 数据源不稳定 | 低 | 中 | 本地缓存 |
| 浏览器兼容性 | 低 | 低 | 限制浏览器版本 |
