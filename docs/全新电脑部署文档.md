# Ocean Mining System 全新电脑部署文档

本文档面向“新电脑上什么都没有”的情况，目标是让项目在本机成功启动。

推荐环境：
- Windows 11 / Ubuntu 22.04+ / macOS 13+
- Node.js 20 LTS
- npm 10+
- PostgreSQL 16+
- PostGIS 3+
- Git

说明：
- 本项目是“前端 + Node.js 后端 + PostgreSQL/PostGIS”结构。
- 前端默认端口：`5173`
- 后端默认端口：`5678`
- WebSocket 默认端口：`8081`
- 如果只启动前端、不启动后端，页面能打开，但很多功能会报错或无数据。

---

## 1. 先确认你要准备什么

新电脑至少需要安装：
- Git
- Node.js
- PostgreSQL
- PostGIS

建议先完成下面 4 个验证，再进入下一步：

1. 验证 Git
```bash
git --version
```

2. 验证 Node.js
```bash
node -v
npm -v
```

期望：
- `node -v` 建议是 `v20.x`
- `npm -v` 建议是 `10.x` 或更高

3. 验证 PostgreSQL
```bash
psql --version
```

4. 验证 PostGIS
先进入 PostgreSQL：
```bash
psql -U postgres
```

再执行：
```sql
SELECT version();
```

如果系统还没装好，这一步先不用继续，按下文安装。

## 5. 初始化 PostgreSQL + PostGIS 数据库

这是本项目能否正常启动的关键步骤。

## 5.1 登录 PostgreSQL

```bash
psql -U postgres
```

输入你安装 PostgreSQL 时设置的密码。

---

## 5.2 执行数据库初始化脚本

退出 PostgreSQL 命令行后，在项目目录执行：
```bash
cd backend
psql -U postgres -f database_postgres.sql
cd ..
```

如果你的 PostgreSQL 用户不是 `postgres`，请换成自己的用户名。

这个脚本会：
- 创建数据库 `ship_monitoring`
- 启用 `postgis`
- 创建业务表
- 创建索引、视图、函数

---

## 5.3 验证数据库是否创建成功

```bash
psql -U postgres -d ship_monitoring
```

进入后执行：
```sql
\dt
```

至少应能看到这些表：
- `monitoring_areas`
- `area_ships`
- `warnings`
- `event_logs`
- `system_config`

再验证 PostGIS：
```sql
SELECT PostGIS_Version();
```

如果能返回版本号，说明 PostGIS 正常。

输入以下命令退出：
```sql
\q
```

## 6. 配置项目环境变量

本项目有两份环境变量：
- 根目录 `.env`：前端
- `backend/.env`：后端

---

## 6.1 配置前端 `.env`

文件位置：
- `.env`

当前关键字段：
```env
VITE_SHIPXY_API_KEY="你的船讯网API Key"
VITE_WINDY_API_KEY="你的Windy API Key"
VITE_API_BASE_URL=/api/backend
```

建议：
- 将 `VITE_SHIPXY_API_KEY` 改为你自己的真实 Key
- 将 `VITE_WINDY_API_KEY` 改为你自己的真实 Key

说明：
- 如果没有真实 API Key，部分船舶和天气相关功能可能不可用

---

## 6.2 配置后端 `backend/.env`

文件位置：
- `backend/.env`

建议修改成类似下面：
```env
PORT=5678
WS_PORT=8081
PUBLIC_URL=http://127.0.0.1:5678
ENABLE_WEBSOCKET=true

WEBHOOK_PATH=/webhook/518f756a-a27e-4c18-bc14-5f62f536d600

DB_HOST=127.0.0.1
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=你的PostgreSQL密码
DB_NAME=ship_monitoring

SHIPXY_API_KEY=你的船讯网API Key
SHIPXY_BASE_URL=https://api.shipxy.com

UPDATE_INTERVAL=600

DEFAULT_WIND_THRESHOLD=15
DEFAULT_WAVE_THRESHOLD=3
```

必须确认这几项正确：
- `DB_USER`
- `DB_PASSWORD`
- `DB_NAME`
- `PORT`
- `WS_PORT`
- `PUBLIC_URL`

## 7. 修改本地部署必须调整的代码配置

这一步非常重要。

原因：
- 当前项目代码中有多处地址写死为外部服务器 IP
- 如果不改，新电脑虽然能把页面跑起来，但前后端不会真正连到本机

以下内容必须改为本机地址。

---

## 7.1 修改 Vite 代理地址

文件：
- `vite.config.js`

找到：
```js
'/api': {
  target: 'http://121.194.93.61:8081',
```

改成：
```js
'/api': {
  target: 'http://127.0.0.1:5678',
```

说明：
- 前端开发时，`/api` 请求会通过 Vite 转发到本地后端

---

## 7.2 修改前端 API 默认地址

文件：
- `src/api/config.js`

将默认生产地址：
```js
'http://121.194.93.61:8081'
```

改成：
```js
'http://127.0.0.1:5678'
```

将 WebSocket：
```js
ws://121.194.93.61:8081/ws
```

改成：
```js
ws://127.0.0.1:8081
```

说明：
- 当前代码中 WebSocket 路径实际使用的是裸端口 `8081`
- 不需要 `/ws`

---

## 7.3 修改 App.vue 里的 WebSocket 写死地址

文件：
- `src/App.vue`

找到：
```js
const WS_URL = 'ws://121.194.93.61:8081';
```

改成：
```js
const WS_URL = 'ws://127.0.0.1:8081';
```

---

## 7.4 修改矿区监测接口写死地址

文件：
- `src/api/miningMonitoring.js`

找到：
```js
const API_BASE_URL = 'http://121.194.93.61:8081/api/mining-monitoring';
```

改成：
```js
const API_BASE_URL = 'http://127.0.0.1:5678/api/mining-monitoring';
```

注意：
- 当前后端代码中未发现 `/api/mining-monitoring` 路由
- 所以即使改成本机，这部分功能也可能仍然不可用
- 这不影响前端主界面启动，但会影响“矿区监测”相关功能

## 10. 启动后验证顺序

建议按下面顺序验证，不要一上来就点所有功能。

## 第一步：验证前端页面是否能打开

检查：
- 页面能正常显示
- 无白屏
- 浏览器控制台没有大量红色报错

## 第二步：验证后端接口是否连通

访问：
- `http://127.0.0.1:5678/api/test/status`

如果通，说明后端没问题。

## 第三步：验证前端是否能访问后端

在浏览器开发者工具 `Network` 中查看：
- 是否有请求打到 `127.0.0.1:5678`
- 或开发模式下是否通过 `5173 -> /api -> 5678` 代理成功

## 第四步：验证数据库是否正常工作

在系统中执行一次需要后端存储的功能，例如：
- 新建监控区域
- 查询区域列表

然后进入数据库查看：
```bash
psql -U postgres -d ship_monitoring
```

执行：
```sql
SELECT * FROM monitoring_areas LIMIT 5;
```

如果能查到数据，说明数据库链路正常。

## 第五步：验证 WebSocket

后端终端应显示客户端连接日志。

如果前端反复提示 WebSocket 重连，优先检查：
- `backend/.env` 中 `WS_PORT`
- `src/App.vue` 中 `WS_URL`
- 8081 端口是否被防火墙拦截

## 11. 常见问题排查

## 问题 1：`npm install` 失败

处理：
- 先检查 Node.js 版本是否过低
- 建议使用 Node.js 20 LTS
- 删除 `node_modules` 后重装

```bash
rm -rf node_modules package-lock.json
npm install
```

Windows 可手动删除 `node_modules` 后再执行：
```bash
npm install
```

---

## 问题 2：后端启动报 PostgreSQL 连接失败

检查：
- PostgreSQL 服务是否启动
- `backend/.env` 中数据库账号密码是否正确
- 数据库 `ship_monitoring` 是否已创建
- PostGIS 是否已安装

验证命令：
```bash
psql -U postgres -d ship_monitoring
```

---

## 问题 3：执行 `database_postgres.sql` 失败

常见原因：
- 没装 PostGIS
- 当前数据库用户权限不足
- 系统本地化不支持 `zh_CN.UTF-8`

如果创建数据库时报本地化错误，可手工创建数据库后再执行表结构部分：
```sql
CREATE DATABASE ship_monitoring;
```

然后进入数据库：
```sql
\c ship_monitoring;
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

再执行剩余 SQL。

---

## 问题 4：前端打开了，但接口请求还在访问外部 IP

说明你还有地址没改干净。

必须再次检查：
- `vite.config.js`
- `src/api/config.js`
- `src/api/miningMonitoring.js`
- `src/App.vue`

搜索命令：
```bash
rg "121.194.93.61|8.130.46.220|8081" .
```

---

## 问题 5：WebSocket 一直重连

检查：
- 后端是否已启动
- `8081` 端口是否被占用
- `src/App.vue` 的 `WS_URL` 是否是本机地址
- 防火墙是否阻止 `8081`

---

## 问题 6：页面能开，但部分数据为空

这是正常可能情况。

原因：
- 某些功能依赖外部 API Key
- 某些数据依赖外部服务或已有数据文件
- 当前后端只明确提供了区域监控和 Copernicus 相关能力
- 前端中仍有部分接口默认依赖外部服务

这类问题不会阻止系统启动，但会影响部分业务功能。

---

## 12. 推荐的完整启动顺序

每次开机后建议按这个顺序操作：

1. 启动 PostgreSQL 服务
2. 启动后端
```bash
cd backend
npm start
```
3. 启动前端
```bash
cd ..

```
4. 打开浏览器访问
```text
http://127.0.0.1:5173
```
5. 先验证后端状态
```text
http://127.0.0.1:5678/api/test/status
```
6. 再进入系统操作

## 13. 最终成功标准

满足以下条件即说明部署成功：
- `npm install` 和 `backend/npm install` 都成功
- PostgreSQL 数据库 `ship_monitoring` 创建成功
- `PostGIS_Version()` 能返回版本
- 后端能正常启动
- `http://127.0.0.1:5678/api/test/status` 可访问
- 前端能正常启动
- `http://127.0.0.1:5173` 能打开系统首页

## 14. 当前项目已确认的本地部署注意事项

本项目代码里目前已确认有以下本地部署风险点：
- `vite.config.js` 中 `/api` 代理默认指向外部 IP
- `src/api/config.js` 中生产环境 API 地址默认指向外部 IP
- `src/api/config.js` 中 WebSocket 地址默认指向外部 IP
- `src/api/miningMonitoring.js` 中接口地址写死为外部 IP
- `src/App.vue` 中 WebSocket 地址写死为外部 IP

所以在新电脑本地部署时，这些位置必须先改成本机地址。
