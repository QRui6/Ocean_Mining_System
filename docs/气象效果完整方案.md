# 🌦️ 深海采矿系统 - 气象效果完整方案

## 一、技术选型

### 1.1 前端技术栈

#### 核心技术
- **Cesium.js** ✅ (已有) - 3D 地球引擎，支持粒子系统
- **Vue 3** ✅ (已有) - 前端框架
- **WebGL** ✅ (Cesium 内置) - GPU 加速渲染

#### 气象可视化技术
| 技术 | 用途 | 性能 | 难度 |
|------|------|------|------|
| PointPrimitiveCollection | 风场粒子 | ⭐⭐⭐⭐⭐ | ⭐⭐ |
| ParticleSystem | 降雨/雪 | ⭐⭐⭐⭐ | ⭐⭐ |
| ImageryLayer | 云层/热力图 | ⭐⭐⭐⭐⭐ | ⭐ |
| CustomShader | 洋流动画 | ⭐⭐⭐ | ⭐⭐⭐⭐ |

**推荐组合**：
- 风场：PointPrimitiveCollection (3000-5000 粒子)
- 降雨：ParticleSystem
- 云层：ImageryLayer + 瓦片服务
- 温度：ImageryLayer + 热力图

### 1.2 数据格式

#### 风场数据 (JSON)
```json
{
  "header": {
    "dx": 1.0,        // 经度间隔
    "dy": 1.0,        // 纬度间隔
    "nx": 360,        // 经度点数
    "ny": 181,        // 纬度点数
    "refTime": "2024-01-01T00:00:00Z"
  },
  "data": [
    {"u": 5.2, "v": -3.1}  // U/V 分量
  ]
}
```
**文件大小**：约 2-5 MB (压缩后 500KB)

#### 云层数据 (PNG 瓦片)
- 格式：256×256 PNG
- 层级：0-8 级
- 像素值：0-255 (云量)
- 总大小：约 100-500 MB (按需加载)

#### 温度数据 (GeoJSON)
```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "geometry": {"type": "Point", "coordinates": [lon, lat]},
      "properties": {"temp": 25.3, "depth": 0}
    }
  ]
}
```
**文件大小**：约 1-10 MB

### 方案对比

| 数据源 | 费用 | 精度 | 实时性 | 难度 | 推荐度 |
|--------|------|------|--------|------|--------|

### 2.1 方案一：纯前端（无后端）

**适用场景**：演示、原型、小规模应用

**数据来源**：
1. **模拟数据** - 前端生成
2. **静态 JSON** - 放在 `public/data/`
3. **第三方 API** - 直接调用（有 CORS 限制）

**优点**：
- ✅ 部署简单，只需静态服务器
- ✅ 开发快速，无需后端知识
- ✅ 成本低，无服务器费用

**缺点**：
- ❌ 数据不实时，需手动更新
- ❌ CORS 限制，无法调用部分 API
- ❌ 无法处理 GRIB2 等复杂格式
- ❌ 无法缓存优化
- ❌ 数据量大时加载慢

**性能**：
- 粒子数：3000-5000 (流畅)
- 数据大小：< 5 MB (可接受)
- 帧率：60 FPS



### 2.2 方案二：前端 + 轻量后端

**适用场景**：生产环境、需要实时数据

**架构**：
```
前端 (Vue + Cesium)
    ↓ HTTP
后端 (Node.js / Python)
    ↓ 定时任务
气象数据源 (NOAA / OpenWeather)
```

**后端职责**：
1. 定时获取气象数据（每 6 小时）
2. 转换数据格式（GRIB2 → JSON）
3. 压缩和缓存
4. 提供 API 接口

**优点**：
- ✅ 数据实时更新
- ✅ 无 CORS 问题
- ✅ 可处理复杂格式（GRIB2）
- ✅ 数据压缩和缓存
- ✅ 可控制数据质量

**缺点**：
- ❌ 需要服务器（成本增加）
- ❌ 开发复杂度提高
- ❌ 需要运维维护

**性能**：
- 粒子数：5000-10000 (流畅)
- 数据大小：压缩后 < 1 MB
- 帧率：60 FPS
- 加载时间：< 2 秒

## 三、性能优化策略

### 3.1 粒子系统优化

#### 粒子数量控制
```javascript
// 根据设备性能动态调整
const isMobile = /Mobile|Android|iPhone/i.test(navigator.userAgent);
const particleCount = isMobile ? 2000 : 5000;

// 根据相机高度调整
const cameraHeight = viewer.camera.positionCartographic.height;
if (cameraHeight > 10000000) {
  particleCount = 3000;  // 远距离少粒子
} else {
  particleCount = 5000;  // 近距离多粒子
}
```

#### 按需渲染
```javascript
// Cesium 按需渲染模式
viewer.scene.requestRenderMode = true;
viewer.scene.maximumRenderTimeChange = Infinity;

// 只在需要时渲染
viewer.scene.requestRender();
```

#### 粒子生命周期
```javascript
// 限制粒子寿命，自动回收
{
  age: 0,
  maxAge: 100,  // 100 帧后重置
  reset() {
    this.age = 0;
    this.position = randomPosition();
  }
}
```

### 3.2 数据加载优化

#### 分块加载
```javascript
// 只加载可见区域的数据
const bounds = viewer.camera.computeViewRectangle();
const data = await fetchWindData(bounds);
```

#### 数据压缩
```javascript
// 使用 gzip 压缩
// 原始：5 MB → 压缩后：500 KB (10倍)
fetch('/api/wind-data', {
  headers: { 'Accept-Encoding': 'gzip' }
});
```

#### 缓存策略
```javascript
// 浏览器缓存 + Service Worker
// 数据有效期：6 小时
Cache-Control: max-age=21600
```

### 3.3 渲染优化

#### LOD (Level of Detail)
```javascript
// 根据距离调整细节
if (cameraHeight > 20000000) {
  // 远距离：低细节
  particleSize = 2;
  updateInterval = 100;  // 每 100ms 更新
} else {
  // 近距离：高细节
  particleSize = 4;
  updateInterval = 16;   // 每帧更新
}
```

#### 批量渲染
```javascript
// 使用 PointPrimitiveCollection 批量渲染
// 比单个 Entity 快 10-100 倍
const collection = new Cesium.PointPrimitiveCollection();
for (let i = 0; i < 5000; i++) {
  collection.add({ position, color, pixelSize });
}
```

## 四、后端方案详解

### 4.1 是否需要后端？

#### 需要后端的情况
- ✅ 需要实时气象数据
- ✅ 数据量大（> 10 MB）
- ✅ 需要处理 GRIB2 等复杂格式
- ✅ 需要多个数据源整合
- ✅ 需要历史数据查询
- ✅ 商业应用，对性能要求高

#### 不需要后端的情况
- ✅ 仅演示用途
- ✅ 使用模拟数据
- ✅ 数据更新频率低（每天/每周）
- ✅ 可接受手动更新数据
- ✅ 预算有限

### 4.2 后端技术选型

#### 方案 A：Node.js (推荐)
```javascript
// 技术栈
- Express.js (Web 框架)
- node-cron (定时任务)
- axios (HTTP 请求)
- grib2json (GRIB2 解析)

// 优点
- 与前端同语言
- 生态丰富
- 部署简单

// 缺点
- GRIB2 处理较慢
```

#### 方案 B：Python
```python
# 技术栈
- Flask / FastAPI (Web 框架)
- APScheduler (定时任务)
- pygrib (GRIB2 解析)
- xarray (NetCDF 处理)

# 优点
- 气象数据处理强大
- 科学计算库丰富
- GRIB2 处理快

# 缺点
- 需要学习 Python
```
