# 气象数据详解 - 你需要知道的一切

## 一、气象数据的本质

### 1.1 什么是气象数据？

气象数据**不是实时测量的**，而是**数值天气预报模型的输出结果**。

```
真实世界的天气
    ↓ 观测站、卫星、雷达测量
观测数据
    ↓ 输入到数值模型
数值天气预报模型 (如 GFS)
    ↓ 计算未来天气
预报数据 (GRIB2 文件)
    ↓ 我们下载
气象可视化
```

### 1.2 数据的时间概念

**关键概念**：
- **参考时间 (Reference Time)**：模型运行的时间
- **预报时间 (Forecast Time)**：预报的未来时间
- **时间步长 (Time Step)**：预报的时间间隔

**举例**：
```
参考时间：2024-01-01 00:00 UTC (模型运行时间)
预报时间：
  - 2024-01-01 00:00 (0 小时后，即"当前")
  - 2024-01-01 06:00 (6 小时后)
  - 2024-01-01 12:00 (12 小时后)
  - ...
  - 2024-01-11 00:00 (240 小时后，即 10 天后)
```

## 二、NOAA GFS 数据详解

### 2.1 GFS 是什么？

**GFS (Global Forecast System)** - 全球预报系统
- **运营机构**：美国国家海洋和大气管理局 (NOAA)
- **模型类型**：全球数值天气预报模型
- **用途**：预报未来 16 天的全球天气

### 2.2 GFS 运行时间表

```
每天运行 4 次：
- 00:00 UTC (北京时间 08:00)
- 06:00 UTC (北京时间 14:00)
- 12:00 UTC (北京时间 20:00)
- 18:00 UTC (北京时间 02:00)

每次运行需要：
- 数据收集：1-2 小时
- 模型计算：2-3 小时
- 数据发布：3-4 小时后

实际可用时间：
- 00:00 UTC 运行 → 04:00 UTC 可下载
- 06:00 UTC 运行 → 10:00 UTC 可下载
- 12:00 UTC 运行 → 16:00 UTC 可下载
- 18:00 UTC 运行 → 22:00 UTC 可下载
```

### 2.3 GFS 数据结构

**一次 GFS 运行产生的数据**：

```
gfs.20240101/00/atmos/
├── gfs.t00z.pgrb2.0p25.f000  (0 小时预报，即"当前")
├── gfs.t00z.pgrb2.0p25.f003  (3 小时预报)
├── gfs.t00z.pgrb2.0p25.f006  (6 小时预报)
├── gfs.t00z.pgrb2.0p25.f009  (9 小时预报)
├── ...
├── gfs.t00z.pgrb2.0p25.f120  (5 天预报)
├── ...
└── gfs.t00z.pgrb2.0p25.f384  (16 天预报)

时间间隔：
- 0-120 小时：每 3 小时一个文件
- 120-240 小时：每 6 小时一个文件
- 240-384 小时：每 12 小时一个文件

总文件数：约 65 个文件/次运行
```

### 2.4 单个文件内容

**一个 GRIB2 文件包含**：

```
gfs.t00z.pgrb2.0p25.f000 (约 500 MB)
├── 地面气压
├── 10m 风速 (U 分量)
├── 10m 风速 (V 分量)
├── 2m 温度
├── 2m 湿度
├── 降水量
├── 云量
├── 500hPa 高度
├── ... (共 100+ 个气象要素)
└── 全球网格数据 (1440 × 721 个点)
```

**我们只需要**：
- 10m 风速 U 分量
- 10m 风速 V 分量

**过滤下载后**：约 50 MB → 2 MB (压缩后)

## 三、数据是"实时"的吗？

### 3.1 严格来说：不是实时

**原因**：
1. 数据是**预报**，不是**观测**
2. 有 3-4 小时的**延迟**
3. f000 文件是"0 小时预报"，相当于"当前状态的最佳估计"

### 3.2 实际上：可以当作"准实时"

**为什么可以当作实时？**

```
时间线：
00:00 UTC - GFS 模型开始运行
01:00 UTC - 收集全球观测数据
02:00 UTC - 模型计算中
03:00 UTC - 模型计算完成
04:00 UTC - 数据发布，可以下载 ✅

04:00 UTC - 我们下载 f000 文件
04:10 UTC - 转换为 JSON
04:15 UTC - 用户看到"当前"风场

实际延迟：4 小时 15 分钟
```

**对于海洋气象来说**：
- 风场变化较慢（小时级）
- 4 小时延迟可接受
- 比实时观测站更全面（全球覆盖）

### 3.3 如何获得"更实时"的数据？

**方案 1：使用观测数据**
```
数据源：气象观测站、浮标、船舶报告
优点：真正实时（分钟级）
缺点：
  - 覆盖不全（只有观测点）
  - 数据稀疏（海洋上很少）
  - 需要插值（精度低）
```

**方案 2：使用快速更新模型**
```
数据源：HRRR (High-Resolution Rapid Refresh)
更新频率：每小时
延迟：1-2 小时
覆盖：仅美国本土
```

**方案 3：组合使用**
```
GFS (全球，6 小时) + 观测数据 (局部，实时)
= 最佳方案
```

## 四、主流气象网站的做法

### 4.1 Windy.com (最流行的气象可视化网站)

**数据来源**：
- GFS (NOAA)
- ECMWF (欧洲中期天气预报中心，最准确)
- ICON (德国气象局)
- NAM (北美中尺度模型)

**更新策略**：
```javascript
// Windy 的做法
每 6 小时检查一次新数据：
  - 00:00 UTC 运行 → 04:30 UTC 下载
  - 06:00 UTC 运行 → 10:30 UTC 下载
  - 12:00 UTC 运行 → 16:30 UTC 下载
  - 18:00 UTC 运行 → 22:30 UTC 下载

数据处理：
  1. 下载 GRIB2 文件
  2. 提取需要的变量
  3. 转换为自定义格式
  4. 切片为瓦片 (Tiles)
  5. 压缩存储
  6. 推送到 CDN

用户访问：
  - 从 CDN 加载瓦片
  - 前端渲染动画
  - 延迟：< 1 秒
```

**时序数据**：
```
Windy 提供：
- 过去 3 天：历史数据（从旧的 GFS 运行）
- 当前：最新 GFS f000
- 未来 10 天：GFS f003-f240

总共：13 天的数据
时间间隔：3 小时
```

### 4.2 Ventusky.com (另一个流行网站)

**数据来源**：
- GFS
- ICON
- WRF

**更新策略**：
```
类似 Windy，但：
- 更新更频繁（每 3 小时检查）
- 使用多个模型（可切换）
- 提供更多气象要素
```

### 4.3 Earth Nullschool (开源项目)

**数据来源**：
- GFS (风场)
- OSCAR (洋流)

**更新策略**：
```javascript

  1. 下载 GFS GRIB2

  5. 前端定时轮询

- GFS (气象)
- AIS (船舶)

**更新策略**：
```

  - 船舶位置：实时

## 六、常见问题解答

### Q1: 为什么不是实时的？

**A**: 因为气象数据是**预报模型的输出**，不是**传感器的测量**。

模型需要：
1. 收集全球观测数据（1-2 小时）
2. 运行复杂计算（2-3 小时）
3. 生成预报结果

所以有 3-4 小时延迟。

### Q2: f000 是什么意思？

**A**: f000 = forecast 0 hours = 0 小时预报 = "当前状态"

```
f000 = 当前（模型认为的现在）
f003 = 3 小时后
f006 = 6 小时后
f024 = 24 小时后（明天）
```

### Q3: 如何获得历史数据？

**A**: 两种方法：

**方法 1：保存旧的预报**
```javascript
// 每次下载新数据时，保留旧数据
// 7 天后，2024-01-01 的 f000 就是"历史数据"
```

**方法 2：下载历史档案**
```
NOAA 提供历史数据：
https://www.ncei.noaa.gov/products/weather-climate-models/global-forecast

但是：
- 数据量巨大（TB 级）
- 下载很慢
- 不推荐
```

### Q4: 为什么主流网站看起来是实时的？

**A**: 因为他们：
1. 每 3-6 小时更新数据
2. 使用平滑动画过渡
3. 延迟很小（< 5 小时）
4. 对于海洋气象，5 小时延迟可接受

### Q5: 我需要下载所有文件吗？

**A**: 不需要！

```
完整 GFS：65 个文件 × 500 MB = 32.5 GB
过滤后：65 个文件 × 2 MB = 130 MB
实际需要：29 个文件 × 2 MB = 58 MB

只下载：
- f000 (当前)
- f006, f012, f018, ... f168 (未来 7 天，每 6 小时)
```

### Q6: 数据准确吗？

**A**: 相对准确，但有误差：

```
预报准确度：
- 0-24 小时：90% 准确
- 24-72 小时：80% 准确
- 72-168 小时：70% 准确
- 168+ 小时：< 60% 准确

对于航线规划：
- 短期（1-3 天）：可靠
- 中期（3-7 天）：参考
- 长期（7+ 天）：仅供参考
```

## 七、实际操作示例

### 7.1 下载当前风场

```bash
# 1. 确定最新的 GFS 运行时间
# 假设现在是 2024-01-08 05:00 UTC
# 最新可用：2024-01-08 00:00 UTC 运行

# 2. 构建下载 URL
BASE_URL="https://nomads.ncep.noaa.gov/cgi-bin/filter_gfs_0p25.pl"
FILE="gfs.t00z.pgrb2.0p25.f000"
PARAMS="lev_10_m_above_ground=on&var_UGRD=on&var_VGRD=on"
DIR="dir=%2Fgfs.20240108%2F00%2Fatmos"

URL="${BASE_URL}?file=${FILE}&${PARAMS}&${DIR}"

# 3. 下载
wget "$URL" -O gfs_current.grib2

# 4. 转换
grib2json -d -n -o gfs_current.json gfs_current.grib2

# 5. 压缩
gzip gfs_current.json

# 结果：gfs_current.json.gz (约 2 MB)
```

### 7.2 自动化脚本

```javascript
// update-weather.js
const axios = require('axios');
const { exec } = require('child_process');
const fs = require('fs');

async function updateWeather() {
  // 1. 计算最新的 GFS 运行时间
  const now = new Date();
  const hour = Math.floor(now.getUTCHours() / 6) * 6;
  const date = now.toISOString().split('T')[0].replace(/-/g, '');
  
  console.log(`更新 GFS 数据: ${date} ${hour}:00 UTC`);
  
  // 2. 下载 f000 (当前)
  await downloadGFS(date, hour, 0);
  
  // 3. 下载未来 7 天 (每 6 小时)
  for (let f = 6; f <= 168; f += 6) {
    await downloadGFS(date, hour, f);
  }
  
  console.log('✅ 气象数据更新完成');
}

async function downloadGFS(date, hour, forecast) {
  const url = `https://nomads.ncep.noaa.gov/cgi-bin/filter_gfs_0p25.pl?` +
              `file=gfs.t${hour.toString().padStart(2, '0')}z.pgrb2.0p25.f${forecast.toString().padStart(3, '0')}&` +
              `lev_10_m_above_ground=on&var_UGRD=on&var_VGRD=on&` +
              `dir=%2Fgfs.${date}%2F${hour.toString().padStart(2, '0')}%2Fatmos`;
  
  const filename = `gfs_${date}_${hour}_f${forecast}.grib2`;
  
  // 下载
  const response = await axios.get(url, { responseType: 'arraybuffer' });
  fs.writeFileSync(filename, response.data);
  
  // 转换
  await convertGRIB2(filename);
  
  console.log(`✅ 下载完成: f${forecast}`);
}

// 每 6 小时运行一次
setInterval(updateWeather, 6 * 60 * 60 * 1000);
```

## 八、总结

### 关键要点

1. **气象数据不是实时的**，是预报模型的输出
2. **GFS 每 6 小时运行一次**，3-4 小时后可下载
3. **f000 是"当前"**，但有 4 小时延迟
4. **主流网站都是每 6 小时更新**
5. **你也应该每 6 小时更新一次**

### 推荐做法

```
1. 每 6 小时下载一次 GFS 数据
2. 下载 f000 + f006-f168 (29 个文件)
3. 转换为 JSON 并压缩
4. 存储到文件系统
5. 前端定时加载新数据
6. 提供时序播放功能

结果：
- 用户看到"准实时"气象
- 可以查看未来 7 天预报
- 可以播放动画
- 延迟可接受（< 5 小时）
```
