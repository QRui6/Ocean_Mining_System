# HWS945 风浪数据定时更新脚本使用说明

适用版本：当前项目 `backend/automation/hws945` 下的脚本。说明日期：2026-11-10。

本说明采用“Windows 运行定时任务，通过网络连接 Docker 中的 PostgreSQL”的部署方式。文中的 `D:\深海项目` 是本机项目路径；迁移机器后需要替换为实际路径。以下命令在 PowerShell 中执行。

## 1. 脚本的作用

每天从 HWS945 网站分别检查六个要素，下载可用文件，计算已启用区域和站点的预报统计，生成 SQL 并自动入库。

| 类别 | 要素代码 | 含义 |
|---|---|---|
| 风场 | `wspd` | 风速 |
| 风场 | `wdir` | 风向 |
| 风场 | `gust` | 阵风 |
| 海浪 | `sigh` | 有效波高 |
| 海浪 | `dire` | 波向 |
| 海浪 | `perd` | 波周期 |

执行规则：

- 六项分别处理。某项文件不存在、下载失败或校验失败时，继续处理其他要素；风场恢复可用后会继续尝试获取。
- 默认在北京时间当天及之前共 7 天中，为每项寻找最新可用的 `t12` 起报批次。因此各要素的实际批次可能不同，也可能早于当天。
- 更新的是预报批次数据，不是实际观测。最新模式拒绝将有效期已经结束的新处理结果自动发布。
- 同一批次、源版本、区域站点定义、处理程序及目标数据库身份未变化时，已成功入库的要素跳过；只有事务提交成功才记录成功状态。
- 同键记录使用 UPSERT，只更新本次要素的指标，保留其他要素。新批次缺失的指标保持为空，不从旧批次复制。
- 默认最新模式只获取各要素最新可用批次，不会自动补齐停机期间每一天的历史批次。

写入的业务表如下：

| 表名 | 用途 |
|---|---|
| `weather_files` | 源文件登记及批次信息 |
| `weather_file_metadata` | 文件中的网格、时间和变量等元数据 |
| `region_forecasts_hourly` | 区域各预报时次统计 |
| `region_forecasts_daily` | 区域逐日统计 |
| `site_forecasts_hourly` | 站点各预报时次数据 |
| `site_forecasts_daily` | 站点逐日统计 |

读取基础资料表 `mining_regions`、`forecast_sites`。不更新地图网格表 `weather_metadata`、`wind_data`、`wave_data`，不生成公报或预警。

SQL 中的 `_hws945_` 开头表是事务内临时表，提交后自动删除；六张业务表没有这个前缀。共享预报表的 `is_latest` 标识整体最新批次，不能据此认定六项要素都已齐全，应结合报告检查各项日期。

## 2. 文件和运行条件

脚本目录：`D:\深海项目\backend\automation\hws945`。

| 文件 | 作用 |
|---|---|
| `run_daily.ps1` | 日常运行入口，实际执行自动入库 |
| `install_daily_task.ps1` | 注册 Windows 每日任务，安装时不立即执行更新 |
| `remove_daily_task.ps1` | 删除定时任务 |
| `daily.py` | 六要素独立调度、生成汇总报告 |
| `pipeline.py` | 下载、计算、SQL 导出与入库 |
| `daily.local.ps1` | 本机 Python、数据和配置文件路径 |
| `database.local.json` | 目标数据库连接配置 |
| `source.example.json` | 当前使用的源站地址、下载模板及重试配置 |

运行条件：

1. Windows 电脑开机，能够访问 HWS945 和数据库。默认任务要求安装任务的 Windows 用户保持登录。
2. Python 3.10 或以上，并安装 `requirements.txt` 中的依赖。本机已准备 `backend\.venv-hws945`。
3. 目标库已具备项目表结构、PostGIS、启用的区域和站点。数据库账号能够读取基础资料、写入上述业务表、使用相应序列并创建临时表。
4. 运行任务的 Windows 账号能够读取脚本和配置，写入原始文件、报告及日志目录。
5. 迁移时保留项目目录结构：脚本还依赖 `automation/mining_overview/process_forecasts_batch.py` 和 `automation/wind_wave/register_weather_batch.py`，不能只复制 `hws945` 文件夹。本项目已应用 NetCDF 缺测值修复，迁移到旧项目时需同步 `processor-mask.patch` 中的改动。

在新机器创建 Python 环境时，可执行：

```powershell
python -m venv 'D:\深海项目\backend\.venv-hws945'
& 'D:\深海项目\backend\.venv-hws945\Scripts\python.exe' -m pip install -r 'D:\深海项目\backend\automation\hws945\requirements.txt'
```

如果独立环境没有 pip，而系统 pip 支持 `--python`，可改用：

```powershell
python -m pip --python 'D:\深海项目\backend\.venv-hws945\Scripts\python.exe' install -r 'D:\深海项目\backend\automation\hws945\requirements.txt'
```

## 3. 配置 Docker 中的数据库

脚本通过 PostgreSQL TCP 连接入库，不需要在本机安装 `psql`，也不需要进入数据库容器执行 Python。

在 Docker 宿主机执行以下命令，确认数据库的端口映射：

```bash
docker ps --format "table {{.Names}}\t{{.Ports}}"
```

例如 `0.0.0.0:15432->5432/tcp` 表示脚本应连接宿主机的 **15432** 端口。

| Docker 所在位置及端口映射 | 配置 `host` | 配置 `port` |
|---|---|---|
| 运行脚本的本机，`5432:5432` | `127.0.0.1` | `5432` |
| 远程服务器，`5432:5432` | 服务器 IP 或域名 | `5432` |
| 远程服务器，`15432:5432` | 服务器 IP 或域名 | `15432` |

远程连接还需数据库监听、宿主机防火墙及 PostgreSQL 访问规则允许脚本电脑访问。若只绑定 `127.0.0.1`，该端口只供宿主机本地访问。输出仅有 `5432/tcp` 而没有宿主机映射时，不能据此认为远程电脑可访问。

编辑 `database.local.json`，示例如下；将占位内容替换为实际配置：

```json
{
  "host": "YOUR_DOCKER_HOST",
  "port": 15432,
  "dbname": "ship_monitoring",
  "user": "YOUR_DATABASE_USER",
  "password": "YOUR_DATABASE_PASSWORD",
  "connect_timeout": 15
}
```

Windows 电脑通常应连接 Docker 宿主机地址，而不是容器名或容器内部 IP。只有脚本也处于相应 Docker 网络等条件下，才适合使用容器服务名。

数据库配置保存为 **UTF-8 无 BOM** 的合法 JSON，不加注释。不要将真实密码写入公开说明书或命令历史。环境变量 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD` 会覆盖 JSON 中的同名连接设置，排错时需检查是否存在旧值。

## 4. 配置每日运行参数

如果 `daily.local.ps1`、`database.local.json` 尚不存在，分别参考 `daily.example.ps1`、`database.example.json` 创建；已有配置直接修改，避免覆盖原账号信息。

`daily.local.ps1` 的配置示例：

```powershell
@{
    PythonExe = 'D:\深海项目\backend\.venv-hws945\Scripts\python.exe'
    DbConfig = 'D:\深海项目\backend\automation\hws945\database.local.json'
    SourceConfig = 'D:\深海项目\backend\automation\hws945\source.example.json'
    OutputDir = 'D:\深海项目\backend\data\hws945\daily'
    RawDir = 'D:\深海项目\backend\data\hws945\raw'
    NoProxy = $true
    LookbackDays = 7
}
```

- `NoProxy = $true`：忽略环境 HTTP 代理直连；如果访问源站必须使用代理，设置为 `$false`。
- `LookbackDays`：最新批次的搜索天数，支持 1～60，默认 7；它不表示补齐这些天的所有批次。
- `SourceConfig` 当前启用公开 DNS 查询，避免本机代理 DNS 导致的慢速连接；保留源站域名的 TLS 证书验证。源站下载路径变化时，在此 JSON 中修改模板。
- Windows PowerShell 5.1 使用含中文路径的 `.ps1` 时，建议保存为 **UTF-8 带 BOM**。

## 5. 首次验证：先不入库

### 5.1 验证数据库端口

将地址、端口替换为实际值：

```powershell
Test-NetConnection YOUR_DOCKER_HOST -Port 15432
```

`TcpTestSucceeded: True` 仅证明端口可达，不代表账号、权限或表结构正确。

### 5.2 只读验证数据库及区域、站点

以下命令使用脚本自己的数据库配置，只读查询基础资料，不写业务表：

```powershell
$hwsPython = 'D:\深海项目\backend\.venv-hws945\Scripts\python.exe'
$hwsCheck = @'
import sys
from pathlib import Path
sys.path.insert(0, r'D:\深海项目\backend')
from automation.hws945.pipeline import read_definitions
data = read_definitions(Path(r'D:\深海项目\backend\automation\hws945\database.local.json'))
print('Active regions:', len(data['regions']))
print('Active sites:', len(data['sites']))
'@
& $hwsPython -c $hwsCheck
```

成功后显示启用区域和站点数量。连接失败先检查数据库配置、环境变量和 PostgreSQL 访问权限。

### 5.3 只检查源站六要素是否可用

以下命令不下载数据文件、不连接数据库、不入库，只生成可用性报告：

```powershell
& 'D:\深海项目\backend\.venv-hws945\Scripts\python.exe' `
  'D:\深海项目\backend\automation\hws945\daily.py' `
  --latest --probe-only --no-proxy `
  --source-config 'D:\深海项目\backend\automation\hws945\source.example.json' `
  --output-dir 'D:\深海项目\backend\data\hws945\daily_probe'
```

结果在 `backend\data\hws945\daily_probe\report.json`。如果必须使用环境代理，删除 `--no-proxy`。

### 5.4 完整试运行：处理并导出 SQL，不入库

以下命令会下载、计算，并只读查询目标库的区域和站点；**不会执行生成的 SQL**：

```powershell
& 'D:\深海项目\backend\.venv-hws945\Scripts\python.exe' `
  'D:\深海项目\backend\automation\hws945\daily.py' `
  --mode export --latest --datasets wind,wave --regional-subset --no-proxy `
  --db-config 'D:\深海项目\backend\automation\hws945\database.local.json' `
  --source-config 'D:\深海项目\backend\automation\hws945\source.example.json' `
  --raw-dir 'D:\深海项目\backend\data\hws945\raw' `
  --output-dir 'D:\深海项目\backend\data\hws945\daily_preview'
```

查看 `daily_preview\report.json` 及 `elements\<要素代码>\` 下的报告与 SQL。没有可用数据的要素不会生成有效导入结果。`daily.py` 按要素输出，各要素目录可以包含自己的 `all_batches.sql`，不要将单个要素文件误认为六项的总文件。

日常自动运行会自己生成并执行 SQL；预览 SQL 无需为了启用定时任务而手动再执行一遍。

## 6. 手动执行一次实际更新

确认以上配置和验证结果后执行。**这一步会将可用数据写入目标数据库。**

```powershell
& 'D:\深海项目\backend\automation\hws945\run_daily.ps1'
```

使用其他运行配置时：

```powershell
& 'D:\深海项目\backend\automation\hws945\run_daily.ps1' -ConfigPath 'D:\实际路径\daily.local.ps1'
```

每个要素批次各自事务提交。一项失败会回滚该项，已经成功提交的其他项保留。全部处理结束后，根据第 8 节检查汇总报告。

## 7. 安装每日定时任务

### 7.1 当前 Windows 用户登录时运行

每天 08:30 执行：

```powershell
& 'D:\深海项目\backend\automation\hws945\install_daily_task.ps1' -At '08:30'
```

时间采用 Windows 系统时区，可通过 `Get-TimeZone` 查看；需要北京时间时应为 `China Standard Time`。08:30 是本地触发时间，不保证官网当日批次此时已经发布。

### 7.2 用户未登录时也运行

安装时指定具备本机任务运行权限的 **Windows 账号**：

```powershell
& 'D:\深海项目\backend\automation\hws945\install_daily_task.ps1' `
  -At '08:30' -Credential (Get-Credential)
```

弹窗填写 Windows 账号及密码，不是 PostgreSQL 账号。该账号必须能访问项目、配置和输出目录，并具备 Windows 批处理任务登录权限；是否需要管理员授权取决于本机策略。

安装本身不立即运行更新。安装器使用固定任务名 `OceanMining-HWS945-Wave`，名称沿用旧版，实际处理全部六项。同名任务重新安装会更新设置；如果需要未登录运行，修改时间、重新安装时仍应保留 `-Credential`。

任务行为：错过执行时间后可补跑；失败后每隔 30 分钟重试，最多 3 次；同一任务不并发，单次执行时间上限 6 小时。未登录运行仍要求电脑开机、网络可用。

### 7.3 查看任务与手动触发

```powershell
Get-ScheduledTask -TaskName 'OceanMining-HWS945-Wave'
Get-ScheduledTaskInfo -TaskName 'OceanMining-HWS945-Wave'
```

需要立即按计划任务身份执行一次时，运行下列命令；**会实际入库**：

```powershell
Start-ScheduledTask -TaskName 'OceanMining-HWS945-Wave'
```

也可以打开 Windows“任务计划程序”，找到此任务查看触发器、运行账号、最近执行时间和结果。

## 8. 日志、报告与成功判断

默认路径如下，修改 `OutputDir` 后以实际配置为准：

| 路径（相对于 `backend\data\hws945`） | 内容 |
|---|---|
| `daily\logs\yyyyMMdd_HHmmss.log` | 每次从 PowerShell 入口执行的日志 |
| `daily\report.json` | 最近一次运行的六要素汇总报告 |
| `daily\elements\wspd\report.json` 等 | 各要素详细批次、失败原因及 SQL 路径 |
| `daily\elements\wspd\applied_state.json` 等 | 各要素已成功提交的状态 |
| `daily\elements\<要素代码>\*.sql` | 本次要素生成的 SQL |
| `raw\年\月\日\` | 缓存的源数据、区域提取文件及来源证明 |

快速查看汇总：

```powershell
$hwsReport = Get-Content -LiteralPath 'D:\深海项目\backend\data\hws945\daily\report.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$hwsReport | Select-Object generated_at, mode, status, database_writes, success_count, skipped_count, failed_count
$hwsReport.elements | Select-Object element, status, batch_date, reason, error_type
```

| 要素状态 | 含义 |
|---|---|
| `applied` | 已处理并提交数据库 |
| `already_applied` | 对应版本已入库，本次跳过重复处理 |
| `skipped` | 请求日期中未找到可用数据 |
| `failed` | 下载、校验、处理或入库失败，查看该项详细报告 |
| `exported` | 导出模式生成了 SQL，未入库 |
| `available` | 探测模式确认有文件，未下载、未入库 |

`latest_element_batches` 列出各项实际使用的起报日期。`database_writes = false` 可能表示本次全部为 `already_applied`，不能仅凭这一项判断失败。

**任务正常结束不等于六项全部成功。** 至少一项成功或确认已入库时，每日入口返回 0，即使其余项失败；六项均无成功时返回 2，配置、基础资料或锁等入口错误返回 1。PowerShell 包装器遇到非零结果会报错，计划任务可据此重试。部分失败不会立即触发任务级重试，下一次每日运行仍会尝试该项；需要当天再次尝试时可手动重跑。

报告会被下一次运行覆盖，日志按运行时间保存。需要长期审计时，应保留每日日志及报告副本。当前脚本没有邮件或消息告警功能。

## 9. 暂停、恢复、修改时间与卸载

暂停后续定时触发：

```powershell
Disable-ScheduledTask -TaskName 'OceanMining-HWS945-Wave'
```

暂停触发不会终止已经开始的更新。需要停止当前任务时：

```powershell
Stop-ScheduledTask -TaskName 'OceanMining-HWS945-Wave'
```

已提交的数据保留；中断时尚未提交的数据库事务回滚，后续重跑可以继续处理。不要在程序运行中删除原始缓存或状态文件。

恢复触发：

```powershell
Enable-ScheduledTask -TaskName 'OceanMining-HWS945-Wave'
```

修改时间，例如每天 09:00，可重新执行安装器的 `-At '09:00'`；未登录运行的任务需同时保留相应 `-Credential` 参数。

删除定时任务：

```powershell
& 'D:\深海项目\backend\automation\hws945\remove_daily_task.ps1'
```

删除任务不会删除数据库数据、脚本、日志和缓存，也不会自动停止已经运行的实例。

## 10. 常见问题

| 问题或现象 | 处理方法 |
|---|---|
| Docker 数据库无法连接 | 检查宿主机 IP、宿主机映射端口、监听地址、防火墙和 PostgreSQL 访问规则；不要将容器内部端口直接当成映射端口。 |
| 端口可达但认证失败 | 检查目标数据库、账号、密码，以及覆盖配置的 `DB_*` 环境变量；任务运行账号与手工运行账号可能有不同环境。 |
| 风场文件 404 | 该项跳过，其他可用项继续。源站恢复原路径后可继续获取；若路径调整，需要修改源配置模板。 |
| 当天没有新数据 | 查看各项 `batch_date`；脚本允许回退最近可用批次，当天文件可能尚未发布。 |
| 任务显示成功但部分要素没更新 | 查看 `skipped_count`、`failed_count` 及逐项报告，任务成功并不要求六项全部可用。 |
| 手动运行成功，定时任务未运行 | 检查任务是否启用、系统时区、运行账号是否登录、账号目录权限、Python 及配置的绝对路径。 |
| PowerShell 提示禁止执行脚本 | 安装器注册的任务带有进程级执行策略参数；手动运行可使用下方独立进程命令，本机组织策略仍可能限制执行。 |
| 报 `HWS945 region missing, inactive, or geometry changed` | 使用已修复浮点精度比较的当前脚本或 `all_batches_geometry_fixed.sql`；若基础区域实际改变，需要依据目标库重新计算，不能直接删除检查。 |
| 提示锁占用 | 检查是否有另一个下载、导出或入库进程正在使用相同原始目录或输出目录，等待其结束后重试。 |
| 更换数据库或恢复了旧备份 | 使用新的独立 `OutputDir` 重新建立处理状态，避免同地址同库名下的旧成功状态导致跳过。不要只依赖原 `applied_state.json`。 |
| 想关闭自己的电脑仍每天更新 | 将完整 Python 运行环境和脚本部署在常开服务器上，由服务器调度；数据库放在 Docker 中不会使本机任务自动迁移过去。 |

手动通过独立 PowerShell 进程运行的命令如下，**会实际入库**：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'D:\深海项目\backend\automation\hws945\run_daily.ps1'
```
